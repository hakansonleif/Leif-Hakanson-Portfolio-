# CLAUDE.md: Leif Hakanson portfolio site

## What this project is
Static one-page portfolio for Leif Hakanson (EHL student, geopolitical risk, economic intelligence, hospitality finance). Plain HTML, CSS and JS in one file. No build step, no framework, no package manager. Hosted on GitHub Pages from branch `main`. Live address: https://hakansonleif.github.io/Leif-Hakanson-Portfolio-/ . Custom domain leifhakanson.me is set in `CNAME` but may not resolve yet. Pages redeploys whenever `main` changes.

The audience is recruiters and hiring managers reading on a phone or laptop. Everything on the page is evidence for a job application, so wrong facts cost him more than ugly CSS.

## Map of the folders
- `index.html`: the whole site (about 3,100 lines, 240 KB). Sections in order: hero, about, experience, research, projects, geopolitics (globe and focus cards), references, skills, contact.
- `assets/papers/`: four PDFs (Ukraine hospitality, Venezuela oil, Hormuz war risk, Monday Effect FTSE MIB).
- `assets/models/`: three Excel models (Deere diagnostic, HAM Leonardo Royal Munich, Westin Las Vegas REF).
- `assets/letters/`: three recommendation letter scans. `assets/certificates/`: OSINT (Centri), IBM Cybersecurity. `assets/cv/`: the CV PDF.
- `assets/og-image.jpg`, `favicon-32.png`, `apple-touch-icon.png`: generated, never hand edited.
- `CNAME`: custom domain. `README.md`: long history of decisions, read it before changing content.
- Build scripts (`build_site.py`, `make_og.py`) are mentioned in the README but exist neither in the repo nor in `~/Downloads/portfolio-site` (checked 13 Nov 2026). Treat `index.html` as the source and edit it directly. Never regenerate the og image or icons without asking him.

## Commands
- Run locally: open `index.html` in a browser, or `python3 -m http.server 8000` in the repo root. All internal links are relative.
- Build: none. Test: none automated. Check by opening the page at 375 px and 1280 px wide.
- Deploy: push to `main`. Work on a branch `donna/<topic>`, open a pull request, merge only when Leif says "merge".
- Before touching anything run `git status`. His local clone (`~/Downloads/portfolio-site`, branch `main`) is behind GitHub and holds uncommitted changes of his own: `index.html` (Emil motion fixes), the CV PDF and the Ukraine paper PDF. Run `git fetch` and compare before any branch. Never reset, stash or overwrite his changes.

## Coding rules
- Keep it one file with no new dependencies. The only external scripts are d3 7.9.0, topojson 3.0.2 and GoatCounter. Fonts: Cormorant Garamond (headings), Inter (body).
- Use the existing CSS variables: `--primary #6B3E3E` (burgundy), `--gold #C9A876`, `--cream`, `--slate`, `--border`. Do not add new colours.
- Chart series colours are `#8A3F3F` and `#A8761F` on purpose (they pass contrast and colour blind checks). Never swap in the brand colours for charts.
- Dashboards reveal with the Web Animations API (`element.animate`), not CSS transitions. A CSS transition started in a zero height panel snaps to its end state.
- Animate only `transform`, `opacity`, shadow, colour or border. Never `transition: all`. Ease out with `cubic-bezier(.23,1,.32,1)`, UI motion under 300 ms. Every animation must have a `prefers-reduced-motion` fallback.
- The globe needs the 50 m world map (`countries-50m.json`). The 110 m file drops Singapore, Luxembourg, Malta and Monaco.
- `OVERVIEW` and `WORKBOOKS` objects in `index.html` are snapshots of the Excel files. If a workbook changes they must be regenerated by hand.
- The `og:` and Twitter meta URLs are absolute and hard coded to the github.io address. Change them if the domain changes.
- Controls must work by keyboard: `role="button"`, `tabindex="0"`, `aria-expanded`, visible focus ring.

## Design rules
- Calm, minimal, premium. Plenty of cream space but no empty gaps: fill a gap with a chart or figure, not padding.
- One accent per area, burgundy for lived in, gold for visited. No emoji, no gradients, no stock icons.
- Text a recruiter reads is plain words and team framing ("we built", not "I did"). No em dashes, no AI sounding phrases ("leverage", "delve", "seamless", "in today's world").
- Phones first: the nav collapses to a hamburger below 768 px; check every new block there.

## Mistakes to avoid (what a weaker model would do here)
1. Rewriting the file or "cleaning it up". It is long on purpose. Make small, exact edits and show the diff.
2. Inventing or rounding facts. Every number must trace to a source file or the CV. Past errors: "61/65 audit checks", "$486B pledged" (it is needs), "eight months" at Shangri-La (it is seven), "Head of" Student Safety Team (he is Supervisor). Check the README correction table first.
3. Adding the Venezuela paper to the CV, or a Forage certificate to the site. Both are decided against.
4. Using the 110 m map, the brand colours in charts, or `transition: all`.
5. Pulling in a framework, build tool or npm package "to make it easier".
6. Changing the visited or lived country lists without being told. Lived: France, Switzerland, UK, Singapore, Luxembourg, Sweden, Australia, USA. Poland and China are not lived in.
7. Applying a colour filter or heavy retouch to his photo. He rejected a green tinted version.
8. Committing straight to `main`, force pushing, or pushing live without his word.
9. Publishing his private details (phone, ehl.ch address after it lapses) in new places.
